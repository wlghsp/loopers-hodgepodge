## 📌 Summary

Redis ZSET 기반의 실시간 상품 랭킹 시스템을 구현했습니다.

### 주요 구현 내용
- **Redis ZSET 랭킹 시스템**: O(logN) 조회 성능으로 실시간 Top N 조회
- **시간 양자화 전략**: 일 단위 키 분리로 롱테일 문제 해결
- **로그 정규화 점수 계산**: 고가 상품의 점수 독점 방지
- **이벤트 가중치 시스템**: 조회/좋아요/주문에 차별화된 가중치 적용
- **콜드 스타트 방지**: 매일 23:50 스케줄러로 10% 점수 승계
- **Ranking API**: 날짜별 랭킹 조회 및 페이지네이션 지원

## 💬 Review Points

### 1. 시간 양자화 전략
일 단위로 키를 분리(`ranking:all:20251226`)하여 롱테일 문제를 해결했습니다. 매일 새로운 랭킹판이 생성되어 신상품도 공정하게 경쟁할 수 있습니다.

**질문**: 일 단위가 아닌 시간 단위나 주 단위 랭킹이 필요한 비즈니스 상황이 있을까요? 실무에서는 어떤 시간 단위를 주로 사용하시나요?

---

### 2. 로그 정규화 선택
주문 금액을 `ln(1 + x)`로 정규화했습니다. 100만원 상품 1개와 1만원 상품 100개가 비슷한 점수를 받도록 했습니다.

**질문**: 정규화 방법으로 `ln(1 + x)`, `sqrt(x)`, 구간별 점수 등을 고려했는데, 실무에서는 어떤 방식을 많이 사용하시나요?

---

### 3. 콜드 스타트 방지
매일 23:50에 오늘 점수의 10%를 내일 키로 미리 복사합니다. 자정 직후에도 랭킹이 비어있지 않도록 했습니다.

**질문**: 10% 가중치를 고정값으로 설정했는데, 시간대나 요일에 따라 다르게 적용하는 것도 고려해볼 만할까요?

---

### 4. 실시간 설정 값 변경
현재 이벤트 가중치(조회: 0.1, 좋아요: 0.2, 주문: 0.6)를 ConfigurationProperties로 관리하고 있습니다. 서버 재시작으로 변경할 수 있습니다.

**질문**: 서버 재시작 없이 실시간으로 가중치를 조정하려면 어떤 방식을 사용하면 좋을까요? DB나 Redis에 저장하는 방법도 고려했는데, 실무에서는 어떻게 하시나요?
